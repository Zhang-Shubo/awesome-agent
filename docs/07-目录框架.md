# 07 · 目录框架

> 机器上的东西放在哪。一个根目录、三个一级目录,每台机器都长一样,agent 和人都不用猜路径。

## 总览

所有 agent 相关的东西收敛到一个根目录(默认 `~/agent`,可通过环境变量 `AGENT_ROOT` 改):

```
$AGENT_ROOT/                     # 默认 ~/agent
├── projects/                    # 项目文件夹 —— AI 创建项目的地方
│   ├── <project-a>/             #   每个项目 = 一个独立 git 仓库
│   ├── <project-b>/
│   └── ...
├── memory/                      # agent 记忆 —— 独立 git 仓库,定时推送
│   ├── MEMORY.md                #   索引(每条记忆一行)
│   └── *.md                     #   一个文件一条记忆
├── skills/                      # 通用 skill —— 独立 git 仓库
│   └── <skill-name>/
│       └── SKILL.md
└── servers/                     # 服务器清单 —— 一台机器一个 md(不进公共仓库)
    └── <server-name>.md
```

三条铁律:

1. **代码不混放**:`projects/` 下每个目录就是一个完整 git 仓库,可独立 clone、独立部署、独立报废;仓库之间不共享文件,共享的东西下沉到 `memory/` 或 `skills/`。
2. **awesome-agent 不收代码,只收登记**:项目代码在各自仓库里,awesome-agent 的 `registry/` 只登记每个项目的**简介 + git 路径**(见下文)。
3. **路径即约定**:CLAUDE.md、部署脚本、skill 里引用这三个目录时一律写 `$AGENT_ROOT/...`,不写死绝对路径,换机器/换人零修改。

## projects/ — 项目文件夹

AI 建新项目的唯一入口。约定:

- 新项目流程:`projects/` 下建目录 → 拷 [templates](../templates) 骨架(CLAUDE.md、config.env.example、deploy.sh、gitignore)→ `git init` → GitHub 建私有仓库 → **到 awesome-agent 的 `registry/` 登记**。
- 每个项目自带 README + 配置模板 + 部署脚本,符合「一个工具一个目录」原则。
- 真实密钥只存在于各项目目录下的 `config.env`(已被 gitignore),永不入库。

## registry/ — 项目登记簿(在 awesome-agent 仓库里)

awesome-agent 仓库下的 `registry/` 目录,一个项目一个 md 文件:

```
awesome-agent/
└── registry/
    ├── README.md
    └── <project-name>.md        # 简介 + git 路径 + 状态
```

登记文件格式(见 [registry/_example.md](../registry/_example.md)):

```markdown
---
name: trade-agent
repo: git@github.com:<you>/trade-agent.git
status: active          # active | paused | archived
runs-on: vps            # local | vps | gpu | 多个用逗号分隔
---

一句话说清这个项目是干什么的,以及对外入口(如有):https://xxx.example.com
```

### 私有登记簿(overlay)

awesome-agent 是公共仓库,`registry/` 里的条目所有人可见。**不想公开的条目**放私有
登记簿目录——`config.env` 的 `REGISTRY_DIR`,缺省 `$AGENT_ROOT/registry`:

```
$AGENT_ROOT/registry/            # 私有登记簿(结构与公共 registry/ 相同)
├── <private-app>.md             #   私有项目条目
├── icons/                       #   自带图标文件(svg/png),面板映射到 /icons/
│   └── <name>.svg               #   条目里写 icon: /icons/<name>.svg 即可引用
└── agents/
    └── <private-agent>.md       #   私有 agent 条目
```

面板启动时合并两处,**同名条目私有覆盖公共**。效果:

- 公共库只放模板 + 愿意公开展示的条目,fork 的人看不到你的私有列表;
- 私有条目跟着 `$AGENT_ROOT` 私有仓库同步,换机器 clone 即恢复;
- 想公开某个项目时,把那个 md 从私有目录挪进公共 `registry/` 即可,格式不变。

这样 awesome-agent 就是全部项目的**索引页**:新机器上恢复环境 = clone awesome-agent → 按 registry 逐个 clone;他人复用 = fork awesome-agent → 清空 registry 从零登记自己的。

## memory/ — agent 记忆

- **本质是一个 git 仓库**,格式沿用「一个文件一条记忆 + MEMORY.md 做索引」:每条记忆带 frontmatter(name / description / type),正文写事实。
- **定时推送,不靠手动**:用 cron(Linux)或 launchd(macOS)定时 `git add -A && git commit && git push`,agent 写完记忆不用管同步;多台机器 = 同一仓库多个 clone,拉取也进定时任务。
- 各项目的 CLAUDE.md 里声明记忆路径指向 `$AGENT_ROOT/memory/`,agent 跨项目共享同一份长期记忆。
- **涉密不入记忆**:记忆仓库按私有仓库对待,但密钥、token 仍然只进各项目的 `config.env`,记忆里只写「密钥在哪台机器哪个文件」。

## servers/ — 服务器清单

- 一台机器一个 md 文件,frontmatter 记**是否有对外 IP、登录方法(ssh alias)、有无 Cloudflare 隧道/DNS 权限、有无免密 sudo、部署通道**,正文自由记述端口段与已知坑;模板见 [templates/server.md](../templates/server.md),默认至少有一台 `local`(本机)。
- 新建项目时(skill `skills/new-project`,动线见 [08](08-项目创建流程.md))据此选部署机器:`cloudflare: true` 的机器才挂域名,`sudo: false` 的机器一律用户级 systemd。
- 清单属于**实例**(个人内容),放 `$AGENT_ROOT/servers/`,不进公共仓库;公共仓库只提供模板与格式。

## skills/ — 通用 skill

- 跨项目复用的 skill 单独成仓,一个 skill 一个目录,每个目录一份 `SKILL.md`(模板见 [templates/SKILL.md](../templates/SKILL.md))。
- 接入 Claude Code:把仓库软链到 Claude Code 的 skill 加载路径,例如
  `ln -s $AGENT_ROOT/skills ~/.claude/skills`
  换运行时(Codex 等)只是换一个软链目标,skill 内容不动。
- 只属于单个项目的 skill 放在该项目仓库里,不进这里;某个 skill 被第二个项目用到时,再上提到 `skills/`。

## 新机器恢复流程

```bash
export AGENT_ROOT=~/agent           # 写进 shell profile
mkdir -p $AGENT_ROOT/projects
git clone <memory 仓库>  $AGENT_ROOT/memory
git clone <skills 仓库>  $AGENT_ROOT/skills
git clone <awesome-agent> && cat awesome-agent/registry/*.md   # 按需 clone 各项目到 projects/
```

四步之后,agent 在这台机器上就有了完整的记忆、技能和项目索引。
