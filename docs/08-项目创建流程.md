# 08 · 项目创建流程

> 从「一个想法」到「面板上一张卡片 + 域名可访问」的标准动线。照着走一遍约 20~30 分钟;纯本地工具走到第 4 步就能收尾。
>
> 本流程已固化为可执行 skill:[skills/new-project](../skills/new-project/SKILL.md),配合 `$AGENT_ROOT/servers/` 服务器清单(见 [07](07-目录框架.md))自动选机、判断是否挂域名、默认注册面板。

## 第 0 步:定三要素

动手之前先定下三样东西,后面每一步都会用到:

| 要素 | 约定 | 示例 |
|------|------|------|
| **名字** | 小写 kebab-case,仓库名 = 目录名 = systemd 单元名 = registry 文件名,四处同名 | `trade-agent` |
| **域名** | `<名字或短别名>.$DOMAIN`,一个项目一个子域名;纯本地工具可以没有 | `trade.example.com` |
| **图标** | 一个 favicon.svg,统一家族风格(见第 3 步),强调色一项目一色 | 深底 K 线 |

三要素想清楚再建仓——名字定错了,仓库/单元/域名/登记四处都要改。

## 总览

```
定三要素 → 建目录建仓 → 图标 → 本地跑通 → 部署(只听 127.0.0.1)
→ Access 鉴权 → 隧道 ingress + DNS → 验证 → 登记收尾
```

## 1. 建目录、建仓

```bash
source config.env            # 拿到 AGENT_ROOT / DOMAIN / GIT_USER
mkdir -p $AGENT_ROOT/projects/<name> && cd $_
cp <awesome-agent>/templates/{CLAUDE.md,config.env.example,deploy.sh,gitignore,notify.mjs} .
mv gitignore .gitignore
git init && git add -A && git commit -m "init from awesome-agent templates"
gh repo create <name> --private --source . --push
```

- CLAUDE.md 按模板骨架填:铁律 → 运行模型 → 目录 → 约定 → 命令 → 环境变量 → 部署 → 已知坑;
- 真实密钥只进本地 `config.env`(已被 gitignore),仓库里只有 `config.env.example`。

## 2. 图标(别漏)

每个上域名的项目都要带 favicon——否则浏览器固定标签页里全是灰色地球,分不清谁是谁。统一家族风格:

```svg
<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 64 64">
  <rect width="64" height="64" rx="14" fill="<项目强调色或渐变>"/>
  <!-- 白色 glyph:文字用 <text>,图形用 <path>/<rect> -->
</svg>
```

- 规格:`viewBox="0 0 64 64"` + `rx="14"` 圆角方块 + 项目强调色底 + 单个白色符号;
- 静态/零依赖前端:`public/favicon.svg` + `<link rel="icon" type="image/svg+xml" href="/favicon.svg">`;服务端有静态白名单的记得把 `/favicon.svg` 登记进去,否则 404;
- Next.js app router:直接放 `src/app/icon.svg`,自动接入;
- 已有透明底深色 PNG logo 的:先垫一层白色圆角方形(256px、radius 56)再当图标,否则深色标签栏上看不见;
- 做完渲一张 PNG 目检(macOS: `qlmanage -t -s 128 -o . favicon.svg`)再部署。

## 3. 本地跑通

- 服务**只监听 `127.0.0.1`**(全局铁律)。代码里写死 `0.0.0.0` 的,先加 `HOST` 环境变量支持;
- 端口先查占用:`ss -tln | grep <port>`(macOS: `lsof -i :<port>`);
- 本地验证:`curl -s -o /dev/null -w "%{http_code}" localhost:<port>/` 得 200。

## 4. 部署

选机器:无状态、需 7×24 → 云主机;要 GPU / 本地资源 / 人在服务在 → 本地机(取舍见 [docs/00](00-依赖清单.md))。

**传输 = git,不用 rsync/tar。** 两种方式:

- **裸仓库 + post-receive 钩子**(推荐,一句 push 全自动,机器不用连 GitHub):

  ```bash
  ssh <机器> 'git init --bare ~/<name>.git && mkdir -p ~/<name>'
  # 钩子 ~/<name>.git/hooks/post-receive(chmod +x):
  #   #!/bin/bash
  #   set -e; unset GIT_DIR
  #   git --git-dir=$HOME/<name>.git --work-tree=$HOME/<name> checkout -f main
  #   cd $HOME/<name> && npm ci && npm run build     # 零依赖项目可省
  #   systemctl --user restart <name>.service
  git remote add deploy <机器>:~/<name>.git && git push deploy main
  ```

- 或走 GitHub:push origin 后上机 `git pull && npm ci && systemctl --user restart <name>`。

服务用**用户级 systemd** 管理(零 sudo,模板见 [templates/app.service](../templates/app.service)、[templates/deploy.sh](../templates/deploy.sh)):单元里 `EnvironmentFile=` 指向机上的 config.env、`Restart=on-failure`,`systemctl --user enable --now <name>`。`config.env` 用 scp 直传,不落中转文件。

**纯本地工具到此为止**,跳到第 7 步收尾;要上域名的继续。

## 5. Access 鉴权(先于 DNS!)

**顺序铁律:先建 Access 应用,再绑 DNS。** 反过来会有约 30 秒"裸奔空窗"——域名已解析但无鉴权,公网直接 200。

默认**所有私有服务都套 Access**;例外只有纯 API 域名(浏览器跨域 fetch 套了鉴权就废)。

```bash
curl -s -X POST -H "Authorization: Bearer $CF_API_TOKEN" -H "Content-Type: application/json" \
  "https://api.cloudflare.com/client/v4/accounts/$CF_ACCOUNT_ID/access/apps" -d '{
  "name": "<name>",
  "domain": "<sub>.'$DOMAIN'",
  "type": "self_hosted",
  "session_duration": "730h",
  "allowed_idps": ["<你的 IdP id,如邮箱 OTP>"],
  "auto_redirect_to_identity": false,
  "policies": ["<你的策略 id,如 only-me>"]
}'
```

- IdP 与策略建一次全局复用,新项目只引用 id(首次配置见 [docs/04](04-隧道与鉴权.md));
- POST 必须带全量字段(缺 type / allowed_idps 会报错);
- 记下返回的 **app id**,写进项目 CLAUDE.md。

## 6. 隧道 ingress + DNS

隧道用**远程管理模式**(改配置只需调 API,不用上机):

```bash
# 先 GET 现有配置 —— ⚠️ PUT 是整体覆盖,必须带全量 ingress 列表
curl -s -H "Authorization: Bearer $CF_API_TOKEN" \
  "https://api.cloudflare.com/client/v4/accounts/$CF_ACCOUNT_ID/cfd_tunnel/<隧道id>/configurations"
# 在 ingress 里插入 {"hostname":"<sub>.$DOMAIN","service":"http://127.0.0.1:<port>"} 后整体 PUT 回去
# 末尾保留 {"service":"http_status:404"}

cloudflared tunnel route dns <隧道名> <sub>.$DOMAIN     # 在有 cert.pem 的机器上执行
```

## 7. 验证(三连)

```bash
ssh <机器> 'curl -s -o /dev/null -w "%{http_code}" localhost:<port>/'      # 本机 200
curl -s -o /dev/null -w "%{http_code} -> %{redirect_url}\n" https://<sub>.$DOMAIN/   # 302 → cloudflareaccess.com
curl -s -o /dev/null -w "%{http_code}\n" https://<同隧道其他域名>/          # 回归:没被 PUT 覆盖误伤
```

改过哪条隧道,就把那条隧道上的**所有**域名回归一遍——PUT 全量覆盖最容易误伤。

## 8. 登记收尾

- [ ] **registry 登记**:在 awesome-agent 的 `registry/<name>.md` 加一个文件(name / repo / status / runs-on + 一句话简介 + 访问入口),commit + push——面板(`web/`)即刻多一张卡片;
- [ ] **CLAUDE.md 补上线信息**:域名、机器、端口、隧道、Access app id、发布命令;
- [ ] **知识库记一笔**:项目文档 + 「已知坑」一节(哪怕暂时为空);
- [ ] **记忆更新**:把新挂的 Access 应用记入 agent 记忆(memory 仓库)。

## 已知坑

- **隧道 PUT 是全量覆盖**——每次改前先 GET,改完全隧道域名回归;
- **先 Access 后 DNS**,消灭裸奔空窗(见第 5 步);
- **Cloudflare 免费版单请求上传上限 100MB**——大文件上传类工具要留直连兜底,长期解法是分片上传;
- **不用 rsync/tar 传代码**(跨境链路经常断流)——一律 git push 部署;
- **wrangler OAuth token 会过期**:隧道 API 报 Authentication error(code 10000)时,先 `npx wrangler whoami` 刷新再重试;注意 Access 用的 API token 和隧道 API 的 token 权限不同,别混用;
- **机器上 sudo 要密码的**,一律用户级 systemd(`~/.config/systemd/user/` + `systemctl --user` + linger),单元里用 `%h` 代替家目录;
- 静态站部署后新路径可能短暂命中边缘缓存的旧 404,几秒自愈,别急着回滚。
