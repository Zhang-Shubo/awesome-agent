# 01 · 个人知识库

> Obsidian 为中枢,「生成即入库」。agent 的一切产出——网页剪藏、视频总结、日报、交易记录——直接写成 markdown 笔记,落进 vault。

## 为什么是 Obsidian

- **纯 markdown 文件**:agent 用最普通的文件写入就能产出笔记,不需要任何 API 或插件;你换编辑器、换平台,笔记还在。
- **wiki-link**(`[[笔记名]]`):agent 产出的笔记之间能互相引用,知识自然成网。
- **多副本同步**:Obsidian Sync(或 Syncthing 等)让本地主力机和常驻服务机各持一份副本,agent 在哪台机器上跑都能写入。

## 核心原则:生成即入库

**产出物直接写 vault,不写任何「事后同步脚本」。**

失败教训:曾尝试「agent 写到共享目录 → 定时 rsync 进 vault」,被系统权限(macOS TCC)、定时任务失效等一路阻击。正确做法是让 agent 把最终产物直接写进 vault 目录——写入动作永远可靠,同步交给 Obsidian 自己。

已知坑:桌面端 Obsidian 不开着就不会推送同步。常驻机上可以跑 headless 同步方案,或接受「打开即同步」。

## 知识库的分区约定

```
vault/
├── project/            # 每个项目一个文件夹 + 「<name> 项目文档.md」
│   ├── _项目情况.md     # 状态总表:所有项目一行一个,生死状态一目了然
│   └── <name>/<name> 项目文档.md
├── cron_log/           # 定时任务产出(日报等),按任务分子目录
├── 网页内容收录/         # 网页剪藏 skill 的落点
├── 视频总结/             # 视频转录总结,按频道分子目录
│   └── transcripts/     # 转录原文,与总结用 wiki-link 互链
└── ...
```

要点:

- **项目文档命名固定** `<name> 项目文档.md`,放同名子文件夹,agent 与人都能按约定直接定位。
- **状态总表**一行一个项目:状态 emoji(🟢 运行中 / 🟡 暂停 / ⚫ 死亡)+ 日期 + 一句话 + 文档入口。项目死亡要补「尸检」:结论 + 数据 + 处置 + 教训。
- **相对日期一律写成绝对日期**(「2026-07-28 拆出」而不是「上周拆出」),agent 和未来的你都不用猜。
- **涉密备忘写在知识库,不写进代码仓**:服务器登录方式、密钥存放位置、隧道配置细节,统一放 vault 里的运维笔记(知识库是私有的,代码仓可能公开)。

## agent 写入知识库的三种范式

### 1. 直接写入(本地 skill)

网页剪藏、视频总结这类 skill 在本地机运行,检测到 vault 目录就直接写:

```
正文提取 → 图片转存 R2 图床 → 改写为公开链接 → 写入 vault/网页内容收录/
```

### 2. 双模式落点(本地 / 云端同一 skill)

同一个 skill 可能在本地跑,也可能在云端沙箱(无 vault)跑。约定:

- 检测到 vault 目录 → 写 vault;
- 检测不到 → 写仓库内 `reports/` 目录并 `git commit && git push`,回到本地后自然汇入。

### 3. 服务回写(常驻服务 → vault 副本)

常驻服务(如交易记录)生成单文件笔记写进服务机上的 vault 副本,文件头注明:

```markdown
> ⚠️ 本文件由脚本自动生成,手动修改会被覆盖。
```

自动生成的笔记永远整文件覆盖,人工笔记永远不碰——两类文件不混写。
