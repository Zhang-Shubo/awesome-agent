# 00 · 依赖清单

> 开始搭建之前,先备齐这 5 项依赖。全部就绪后,再从 [docs/01](01-知识库.md) 开始按支柱搭建。

## 总览

| # | 依赖 | 用途 | 费用 |
|---|------|------|------|
| 1 | 一台常开的机器 | 跑 agent 与常驻服务的宿主 | 已有电脑 ¥0 / 云主机约 ¥30~60 每月 |
| 2 | Cloudflare 账号 | 隧道上公网 + 鉴权 + 存储 + 静态站 | 免费套餐够用 |
| 3 | 一个域名 | 应用的外网入口,一切子域名挂在它下面 | 约 ¥70 每年 |
| 4 | GitHub 账号 | 存放项目代码与通用代码(模板、memory、skills) | 免费(含私有仓库) |
| 5 | Claude 账号 | agent 运行时(Claude Code),后续可换/加 Codex 等 | Pro 订阅或 API 按量 |

最小可用配置 = 你现在的电脑 + Cloudflare 免费套餐 + 一个域名 + GitHub 免费账号 + Claude 订阅。**固定成本只有域名年费和 Claude 订阅。**

## 1. 计算设备:个人电脑或云主机

agent 和它部署的服务总要跑在某台机器上。两条路线,可以先走 A 后加 B:

**路线 A:个人电脑(零新增成本)**

- macOS / Linux 直接可用;Windows 建议走 WSL2。
- **已知限制:电脑休眠时隧道随之断开,外部无法访问你的服务。** 对策三选一:
  1. 接受它——个人工具"人在服务在",睡觉时不可用也无妨;
  2. 关闭休眠(macOS: `sudo pmset -a sleep 0`,插电常开);
  3. 对必须 7×24 的服务,单独挪去路线 B。
- 家用宽带没有公网 IP 也完全没关系——对外访问全部走 Cloudflare Tunnel(见 [docs/04](04-隧道与鉴权.md)),不需要端口映射。

**路线 B:云主机(7×24 常驻)**

- 最低配即可起步:1C1G、任意地域、Ubuntu LTS。所有服务只监听 `127.0.0.1`,安全组可以一个入站端口都不开(SSH 也可走隧道)。
- 适合放定时抓取、通知推送、需要随时在线的 Web 应用。
- 服务用**用户级 systemd** 管理(见 [templates/deploy.sh](../templates/deploy.sh)),零 sudo,可独立部署、独立报废。

## 2. Cloudflare 账号

一个免费账号同时提供四样东西,这套脚手架的"边缘层"全在这里:

| 产品 | 在本项目中的角色 | 免费额度 |
|------|-----------------|---------|
| Tunnel | 把任何机器上的 `127.0.0.1` 服务安全暴露成 `xxx.你的域名` | 无限隧道 |
| Access | 公网入口的统一鉴权:邮箱验证码 / 白名单,应用无需自己写登录 | 50 用户内免费 |
| R2 | 对象存储:图床、文件、附件 | 10 GB 存储,出流量免费 |
| Pages | 静态网站托管:个人站、agent 成果对外发布 | 无限站点 |

注册后第一件事是把域名(下一节)的 DNS 托管到 Cloudflare——Tunnel 和 Access 都依赖这一点。

**全局铁律在此生效:所有自建服务只监听 `127.0.0.1`,对外一律走 Tunnel + Access。** 任何机器上不开公网端口,安全模型收敛到 Cloudflare 一处。

## 3. 域名

- 一个你自己的域名,是所有应用的外网入口:`app1.example.com`、`notes.example.com`……子域名不限量,新应用上线只是多一条隧道路由。
- 在哪买都行(Cloudflare Registrar 成本价,也可任意注册商购入后把 NS 指向 Cloudflare),关键是 **DNS 必须托管在 Cloudflare**。
- 费用约 ¥70/年(`.com` 档),是这套系统唯一逃不掉的年费。
- 选购建议:短、好拼写、别用生僻后缀(部分企业网络会拦冷门 TLD)。

## 4. GitHub 账号

代码与"可复用资产"的家,免费账号即可:

- **项目代码**:每个 agent 项目一个仓库,私有仓库不限量。
- **通用代码**:本脚手架(awesome-agent)、模板、skills、memory 等跨项目复用的部分,单独成仓,他人 fork 即用。
- **涉密不入库**:仓库只放 `config.env.example` 模板,真实密钥只存在于部署机(见 [templates/config.env.example](../templates/config.env.example))。
- 建议顺手完成:配好 SSH key 或 `gh auth login`;agent(Claude Code)会直接用 `gh` 建仓、发 PR、查 issue。

## 5. Claude 账号(agent 运行时)

- 默认运行时是 **Claude Code**:登录 Claude Pro/Max 订阅,或配 API key 按量付费。订阅制对"每天高频使用"的个人 agent 更划算。
- 装好后 agent 就是你的施工队:本清单之后的所有搭建步骤(建隧道、配 R2、写部署脚本)都可以直接让它替你做。
- **不锁定单一供应商**:工程约定(CLAUDE.md、skill、部署模板)刻意与具体 agent CLI 解耦,后续可平移/并行支持 Codex 等其他运行时——换 agent 不需要重搭基础设施。多后端策略见 [docs/05](05-agent-工程约定.md)。
