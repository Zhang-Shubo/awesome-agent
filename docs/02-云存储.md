# 02 · 云存储

> Cloudflare R2 做统一对象存储:图床、电子书、附件全放这里。S3 兼容、免出口流量费、免费额度对个人绰绰有余。

## 为什么是 R2

- **S3 兼容 API**:`aws` CLI、任何 S3 SDK、甚至手写 SigV4 都能用。
- **免出口流量费**:图床/文件下载不心疼。
- **自定义公开域**:绑一个 `r2.<你的域名>`,所有对象获得稳定公开 URL——这是「模型看图」「博客配图」「笔记图床」的基础。
- 和隧道、网站、Access 同在 Cloudflare 一个控制台,心智负担最小。

## 统一环境变量口径

所有项目共用同一套变量名,agent 在任何项目里都不用重新学:

```bash
R2_ENDPOINT=https://<account_id>.r2.cloudflarestorage.com
R2_BUCKET=<bucket>
R2_ACCESS_KEY_ID=xxx
R2_SECRET_ACCESS_KEY=xxx
R2_PUBLIC_BASE_URL=https://r2.example.com   # 或 pub-xxx.r2.dev
R2_KEY_PREFIX=webclips/                     # 每类用途一个前缀
```

**key 前缀即命名空间**:`webclips/` 网页剪藏图、`notes/` 笔记附图、`blog/<slug>/` 博客配图、`books/` 电子书……一个桶,前缀分区,权限与清理都好办。

## 三种上传方式(按依赖从多到少)

### 1. `aws s3 cp` CLI(脚本里最省事)

```bash
AWS_ACCESS_KEY_ID=$R2_ACCESS_KEY_ID \
AWS_SECRET_ACCESS_KEY=$R2_SECRET_ACCESS_KEY \
aws s3 cp ./img.png "s3://$R2_BUCKET/webclips/img.png" \
  --endpoint-url "$R2_ENDPOINT"
```

凭证经环境变量注入子进程,不落盘、不进 shell history。

### 2. S3 SDK(应用代码常规选择)

任何语言的 S3 SDK 指到 R2 endpoint 即可。

### 3. 零依赖手写 SigV4(值得收藏的骨架件)

Node 标准库 `node:crypto` 即可实现完整的 S3 SigV4 签名 PUT/DELETE——约百行代码,换来整个项目零依赖。适合「部署=拷文件」的极简服务。

配套的安全习惯:

- **magic-number 嗅探文件类型**,不信客户端的 content-type;
- 上传大小上限(如 8MB);
- 生成文件名走白名单模式(如 `img_[0-9a-f]{12}.(png|jpg|gif|webp)`),永不使用用户提供的文件名。

## 典型用途

| 用途 | 做法 |
|------|------|
| 网页剪藏图床 | 剪藏 skill 下载原图 → 传 R2 → 笔记里改写为公开链接。R2 未配置则降级保留原外链,单图失败保留原链继续——**降级路径先想好** |
| 博客配图 CDN | 路径规范 `blog/<slug>/<NN>-<类型>-<名>.png`,markdown 里直接引公开域 |
| 模型「看图」 | R2 公开 URL 作为 image 传给模型 API;URL 要过严格白名单正则(尤其当 URL 会被拼进 shell 命令时) |
| 无状态服务的持久层 | 电子书、笔记、进度全存 R2,服务器无状态、无数据库,换机器重部署不丢数据 |
